# 《崇祯·宦海浮沉》持续改进路线图

> 体检日期：2026-11-18  
> 体检范围：Web 桌面端、手机横屏 Web、Android 原生端、事件库、测试与构建链  
> 结论口径：只写仓库里能读到、脚本能跑出来的事实；推演与建议单独标注。

---

## 0. 一句话结论

**这个项目现在不缺内容，也不缺工程能力；缺的是“让普通玩家活到能看见内容”的那一段体验。**

当前最该做的不是再加 100 个事件，而是：

1. 把“属性归零即死”改成“归零先给一次绝境求生”；
2. 把首小时的目标、反馈和风险讲清楚；
3. 让每一局结束时，玩家知道自己为什么死、下一局想试什么；
4. 在这三件事验证有效之后，再投入美术、音频和发行。

## 1. 体检：项目现在是什么水平

### 1.1 内容资产：已经是大体量

| 可玩事件 | **434 条** |

这是“商业级内容量”的底子。问题不在数量，在到达率。

### 1.2 工程质量：明显高于个人项目平均线

- 单元测试：**110 个测试文件 / 865 个用例通过 / 1 跳过**；
- Playwright 侧：冒烟、布局、存档模糊、崩溃压力、死锁、性能预算、手机开局/骰子等多套脚本；
- 事件体检：事件结构、叙事字段、历史年号/人物、选项数量等多项审计当前为 **0 问题**；
- 构建链：TypeScript 严格检查、Vite 构建、GitHub Actions 自动部署、Android `assembleDebug` 与单测均通过；
- 首屏：标题屏 **0.92 MB / FCP 388 ms**；开局首卡 **2.56 MB / 2.73 s（本地）**。

工程侧已经不是瓶颈。真正的瓶颈在产品和体验。

### 1.3 实际可玩性：两组 30 局模拟，暴露了核心矛盾

> 口径：本地 `simulateRun`，寒门，seed 1..30，标准事件池，分别跑“稳态”和“苟活”两种策略。不是人类玩家样本，但足以看方向。

| 策略 | 平均局长 | 触达事件 | 触达结局 | 终局归零原因 |
| --- | --- | --- | --- | --- |
| steady（稳态） | **23 个月**（不到崇祯三年） | 178 / 434 | **6 / 49** | 清议 11、财帛 6、道德 6、士绅 6、中官 3、圣眷 2 |
| warden（苟活） | **165 个月**（约 13 年 9 个月） | 396 / 434 | **4 / 49** | 无归零；主要结在殉国、落草、东林烈士、中兴 |

两个结论必须同时看：

- **普通策略活得太短**：23 个月就结束，中后期 300 多条事件根本看不到；
- **最能活的策略反而结局最窄**：苟活到 1644，却被历史主线收束到 4 个结局。

也就是说，当前不是“选择不够多”，而是：

> **前期被生存线卡死，后期被历史线收束。玩家能做的选择，没有真正改变“这一局长什么样”。**

### 1.4 内容质量：合格，但开始出现“批量写作感”

- 事件结构、叙事字段、年代硬伤：当前审计 0 问题；
- 但重复段落体检：**865 组 / 2488 次重复**，散文覆盖率 **9.89%**、冗余率 **6.27%**；
- 最高重复段落出现 7 次，集中在贪墨、赈灾、朝廷拨款、温体仁等模板化后果；
- 557 个 flag 里 197 个“只写不读”；虽然通过履历表让玩家 100% 看得见，但机制上仍是“做了但没改变什么”。

这不是 bug，是内容工业化后的必然副作用：**后果文案开始复用，选择的因果感变弱。**

### 1.5 表现层：目前仍是“可玩的文字原型”，不是“能卖的作品”

- 标题屏、取名屏、出身屏、牌桌都是纯黑底 + 金线 + 文字，几乎没有场景美术；
- 事件卡没有插图，人物没有立绘，只有极简头像/文字；
- BGM 只有一条循环，缺少环境音与关键音效；
- 手机端已经紧凑，但事件区下半屏大面积空置，缺少视觉锚点；
- 线上地址仍是 `chongzhen-game-fixed`，品牌名在标题、README、APK 文件名之间不完全统一。

工程上这是“干净”，产品上这是“没有记忆点”。

## 3. 路线图：先修体验，再做深度，最后做表现

### P0 · 体验修复包（建议 2 周）

目标：让普通玩家活到 5 年以上，并且知道自己为什么死。

| 动作 | 具体做法 | 验收 |
| --- | --- | --- |
| **归零改为“绝境”而非即死** | 八条归零死线任一归零时，先触发一张“绝境”事件：2–3 个代价选项（破财、丢官、损体质、失清议等）；每维每局最多救一次；第二次归零或拒绝代价才结案 | 稳态 30 局平均局长 23 → **60–90 个月** |
| **三档难度变成三种体验** | 史话：24 个月宽限 + 每维一次绝境；标准：12 个月宽限 + 每维一次；铁人：无绝境、无撤销、单独成就 | 三档的局长/结局分布明显不同 |
| **风险预告** | HUD 对最危险的 1–2 项标黄；下月预计会归零时给一句“再拖一个月就断”的明确提示 | 新手能在归零前做出反应 |
| **本局志业（不加强制引导）** | 开局选一个“志业”：升迁 / 清名 / 家族 / 活命；显示 3 个里程碑；结局评价围绕志业结算；可跳过，不做新手教学 | 玩家第一局有明确方向 |
| **首卡提速** | 第一张卡前只加载序章 + 1628 核心历史，gray/ending/1627 过渡延后；目标 **1.2 MB / <1.5 s 本地 / <3 s 4G** | 首卡等待不再打断情绪 |
| **死亡归因** | 结局屏第一行写“直接死因：清议归零”，并给“下一局可尝试：先保清议或走内廷线” | 玩家能说出自己为什么死 |

### P0.1 执行记录（2026-11-18）

上面那条“P0 未过验收线”是 P0 当时的结论。P0.1 把真正的死因拆开后，改用三根杠杆：

| 杠杆 | 改动 | 解决什么 |

#### 整数化：不是只改显示

用户实测看到圣眷出现 `32.5` / `-2.5`。根因是属性结算先乘难度倍率（简单 1.5 / 标准 1.0 / 铁人 1.2）和出身修正（如圣眷 0.8/0.9/1.2），再用 `current × 50%` 做跌幅上限，`65 × 50% = 32.5` 直接落进 `Double` 状态。

修复落在**落账处**，不是只把界面 `toFixed`：

- Web `damageCap.ts`、`useGameEngine.ts`：属性、五方态度、隐藏属性、体质消耗、结算面板 `appliedEffects` 差值全部 `Math.round`；
- `StatusPanel.tsx` 的国势显示/进度/颜色档位统一用整数；
- Android `EffectApplier.kt` 同步：`capDamage` 整数上限，属性/五态/隐藏最终 `roundToInt().toDouble()`。

固定用例：`圣眷 65` 遇 `-100` → 单次掉 32、落账 33、结算面板 -32，不再出现半整数；`acceptance.normalCurve` 还逐局检查终局属性、八条归零线、门控值都是整数。

#### 归零倒计时按“仍在警告带内”累计（2026-11-18）

风险 HUD 之后复核早期破产，发现上一版逐维倒计时还留了一个反直觉缺口：`flagTurns` 只在第一次警告时写一次。玩家把财帛从 0 养回 38、士绅从 0 养回 35，只要过了 30 个月，下一次见底仍按旧警告收尾。轨迹里 seed 5 的财帛 `0→12→38→…→0`、seed 9 的士绅 `0→18→35→…→0` 都是这个形状：玩家看到的是“我已经缓过来了”，引擎记的是“你曾经归零过”。

这次把倒计时语义改成**只累计仍在警告带内的月份**：

| 项 | 规则 |
| --- | --- |
| 恢复线 | 财帛/体质 20，其余六维 15（与风险 HUD 的 `warnAt` 同口径） |
| 计时 | 某维带 `归零警告·X` 且当前值高于恢复线时，把该 flag 的 `flagTurns` 推到本月 |
| 死亡 | 仍然是“该维归零 + 警告票满 30 个月”；但 30 个月必须是在警告带内连续累计，恢复后重新起算 |
| 不做 | 不清除警告 flag、不重发警告卡；图鉴、死因映射和“归零两次才要命”的文案不变 |

实现落点：`src/data/zeroWarningEvents.ts` 的 `ZERO_WARNING_RECOVERY` 与 `refreshZeroWarningCountdown()`；`useGameEngine` 在 `handleChoice` 的 `setCharacter` 与 `handleNextMonth` 的月度 `setCharacter` 两处调用。Android `GameEngine` 同步：抉择后与 `advanceMonth` 各调用一次同名私有方法，`BoundaryEngine.doomedBy` 继续读 `character.flagTurns`。

窄样本（20 局、normal、steady、寒门、seed 1–20）复测：

| --- | --- |
| 月数序列 | 35,55,57,65,68,68,78,79,85,85,88,97,98,99,103,104,104,113,116,157 |
| 中位 / 均值 | **86.5 / 87.7 个月** |
| p25 / 最短 | 68 / 35 |
